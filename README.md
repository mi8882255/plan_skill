# plan-tree — установка и перенос

Личный (personal) Claude Code skill. Основная документация протокола — в
`SKILL.md`, этот файл — только про установку/перенос, не про то, как
пользоваться инструментом.

## Где он должен лежать

```
~/.claude/skills/plan-tree/
├── SKILL.md
├── README.md          (этот файл)
├── install.sh
└── templates/
    ├── node.md
    └── _meta.json
```

Личный (`~/.claude/skills/...`) уровень делает skill доступным из **любой**
рабочей директории на этой машине, в отличие от project-level
(`<project>/.claude/skills/...`), который виден только внутри одного
проекта. Если переменная окружения `CLAUDE_CONFIG_DIR` задана — базовый
путь не `~/.claude`, а её значение; подставляйте его везде ниже.

Данные конкретных деревьев планирования (`plan/<idea-slug>/...`) НЕ входят
в skill и не переносятся этим README — они живут в рабочей директории
каждого проекта и переносятся вместе с самим проектом (git/rsync/архив),
независимо от того, куда перенесён skill.

## Установка на новый компьютер

Самый простой способ — скопировать всю папку на новую машину (через
AirDrop/scp/флешку/т.п.) и положить её по тому же пути:

```bash
# на новой машине, после того как папка plan-tree уже скопирована
# куда-нибудь (например в ~/Downloads/plan-tree)
bash ~/Downloads/plan-tree/install.sh ~/Downloads/plan-tree
```

Или, если у вас уже есть доступ к исходной машине по сети (scp/ssh):

```bash
scp -r user@old-machine:~/.claude/skills/plan-tree /tmp/plan-tree
bash /tmp/plan-tree/install.sh /tmp/plan-tree
```

`install.sh` сам определит правильный целевой путь (учитывая
`CLAUDE_CONFIG_DIR`, если она задана), проверит, что в источнике нет
абсолютных путей текущей машины (которые сломались бы на новой), и
предупредит, если на новой машине уже есть другая версия skill, вместо
того чтобы тихо её перезаписать.

После установки запустите `/reload-skills` в любой открытой сессии Claude
Code (новые сессии подхватят автоматически без этой команды) и проверьте
`/skills`, что `plan-tree` появился в списке.

## Что install.sh НЕ делает

- Не переносит данные конкретных деревьев (`plan/<slug>/`) — это отдельные
  файлы проекта, копируйте их как часть самого проекта.
- Не переносит `skillOverrides` из `~/.claude/settings.json`, если на
  старой машине видимость skill была настроена вручную через `/skills` —
  перенесите этот блок сами, если он у вас есть.
- Не трогает `~/.claude/skills/synced/` — это зарезервированный
  машинно-специфичный кеш плагин-синхронизации, он не часть переноса.

## Удаление / откат

```bash
rm -rf ~/.claude/skills/plan-tree
```

Данные деревьев (`plan/<slug>/`) при этом не удаляются — они не внутри
skill.
